One town. One Pokémon per project.

Working with several coding agents can get confusing. You have to switch between terminals just to see what's happening.

Pokémon Agents gives each project a Pokémon and a place in the town. You can look around to see which agents are working, which have finished, and which are waiting for your reply.

It's a different way to keep track of your coding sessions.

See when an agent needs you

When an agent has a question, or needs you to say yes to something, its Pokémon comes and finds you.

A little sign pops up over its head, like in the Pokémon games. There are four. Here is what each one means.

Answer without leaving the game

You can answer an agent right here in the game. If you want the detail, you can open its terminal too.

You can also start new work and see what you did recently, without leaving the town.

Evolution

Your Pokémon evolves by the same rules as the games. The difference is what sets it off: your real coding work.

Levelcommits, merges, passing tests and sessions all add experience
Stonea stone you won from a gym badge, for the ones that need one
Friendshipthe days you show up, and the work you do. Day or night decides Espeon or Umbreon.
Tradea session passing work to a helper agent, holding an item if one is needed

Every Gen 1 and 2 evolution rule is in here, taken from PokéAPI. Even Tyrogue, who picks its path from your commits against your passing tests.

Get your Pokémon town running

Pokémon Agents is free and open source, and runs locally on your Mac. You'll need macOS, Node.js 22, and Claude Code.

1 Install the dependencies
npm install
2 Set up the project
npm run setup
3 Start Pokémon Agents
npm start

Open http://127.0.0.1:7880 in your browser to see your town. View the full setup guide on GitHub →

MIT licensed · runs locally · no account, no cloud, no telemetry

Runs on your Mac

Pokémon Agents runs on your own machine and opens in your browser. It reads your Claude sessions to show what your agents are doing.

Your session data and game progress are stored locally. The app does not send telemetry.
